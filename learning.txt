	adduser username
3. set or change password
	passwd username
4. Add user to group
	usermod -aG groupname username {a- append, G- group>}
5. Delete user
	userdel username { not remove directory}
6. Delete user and home directory
	userdel -r username

Creataing LVM


1. Check disks
	lsblk

	pvcrete /dev/sda dev/sdb /dev/sdc
3. Create Volume Group
	lvcreate lvname /dev/sda /dev/sdb /dev/sdc

	# Use all remaining free space (extents)

	mkfs.xfs /dev/vgname/lvname
6. Mount lvm

	mount /dev/vgname/lvname /dirname

ACL (Access Control List) for permission on linux +
1.  Give Bob Read Access Using ACL
    setfacl -m u:bob:r /secret.txt
        setfacl - set an ACL
        -m      - Modify an ACL
        u:bob:r - User Bob gets Read permission
2.  Verify
    getfacl /secret.txt
3. Mask
    setfacl -m m:r-- /secret.txt  { max permission on file by acl}
4. Remove a acl
    setfacl -x u:bob /secret.txt
5. Remove all ACls
    setfacl -b file
6. Default ACL
    setfacl -d -m g:developers:rwx /project
        -d    This is the important part.
        It means:
        Default ACL
        Not for the directory itself.
        For future files and directories created inside it.
7. Acl mask
		setfacl -m m:r-- /secret.txt  { m mask is maximum allowed}

Cron	At
Repeating jobs	One-time job
Every minute/day/week/month	Runs once
Stored in crontab	Stored in at queue

Each user has their own crontab (cron table).
View
	crontab -l
Edit
	crontab -e
Remove
	crontab -r

Cron Syntex :
* * * * * command_to_run
│ │ │ │ │
│ │ │ │ └── Day of Week (0–7)
│ │ │ └──── Month (1–12)
│ │ └────── Day of Month (1–31)
│ └──────── Hour (0–23)
└────────── Minute (0–59)
* means every possible value
1. Step Values (*/)
	*/5 * * * * Every 5 minutes
2. Lists (,)
	0 9,13,17 * * * run at 9:00 am , 1:00 pm ,5:00 pm
3. Ranges (-)
	0 9-17 * * *	run every hour from 9 am to 5 pm

        Container : Running (or stopped) instance of image
        Registry: Repository that stores images

    2.  podman images
    3. podman run --name myubi -it registry.access.redhat.com/ubi9/ubi
        run : create and start a container
        --name myubi : assing the name myubi
        -i  : keep STDIN opne (interactive)
        -t  : allocate a terminal (TTY)

    Run a Container in the Background

        podman run -d --name web registry.access.redhat.com/ubi9/ubi sleep infinity
            -d	Detached (background) mode
            --name web	Name the container web
            sleep infinity	Keep the container running indefinitely
    2. Enter a Running Container
        podman exec -it web /bin/bash

        `podman start -ai`                              | `podman exec -it`
        | Starts a stopped container and attaches to it | Opens a new shell inside an already running container |
        | Used when the container is stopped            | Used when the container is already running            |

Podman Part 2 - Port mapping ( -p)
    Imagine you're running Apache inside a container.
        Host Port = 8080
        Container Port = 80
    start
        podman run -d \
        --name testweb \
        -p 8080:80 \
        registry.access.redhat.com/ubi9/ubi \
        sleep infinity
    check :
        podman port testweb
            Podman publishes the container's port 8000 on the host's port 8080. Any request sent to the host on port 8080 is forwarded by Podman to port 8000 inside the container.
            Podman does not create the service; it only forwards traffic to the service.

Boot Process & GRUB
    Power Button (The motherboard firmware takes control.) : BIOS / UEFI (POST) : Boot Device : GRUB2 : Linux Kernel : initramfs : systemd (PID 1) : Services Start : Login Screen

    Q1. What is the job of BIOS/UEFI?
    BIOS or UEFI is the firmware that starts when the computer is powered on. It performs the Power-On Self-Test (POST) to check hardware like the CPU, RAM, keyboard, and storage devices. After verifying the hardware, it finds the bootable device and transfers control to the bootloader (GRUB).

    Q2. What is POST?
    POST stands for Power-On Self-Test. It is the first hardware check performed by BIOS/UEFI when the computer starts. It verifies that important hardware components such as RAM, CPU, keyboard, and storage devices are working properly before the operating system begins to load.

    Q3. What is GRUB2?
    GRUB2 (GRand Unified Bootloader) is the Linux bootloader. It displays the boot menu if multiple operating systems are installed and allows the user to choose which operating system to start. After an operating system is selected, GRUB loads the Linux kernel into memory.

    Q4. Who loads the Linux kernel?
    The Linux kernel is loaded by GRUB2. After BIOS/UEFI finishes its work and selects the boot device, GRUB2 loads the selected Linux kernel into memory and passes control to it so the operating system can continue booting.

    Q5. What is the Linux kernel?
    The Linux kernel is the core (heart) of the operating system. It manages hardware resources such as the CPU, memory, storage devices, network devices, and processes. It also handles system calls and acts as a bridge between hardware and user applications.

    Q6. What is initramfs?
    initramfs (Initial RAM Filesystem) is a temporary filesystem loaded into memory by the kernel during boot. It contains the drivers and modules needed to detect storage devices, load filesystems, and mount the real root filesystem (/). Once the real root filesystem is mounted, initramfs has completed its job.

    Q7. What is PID 1?
    systemd is the first userspace process started by the Linux kernel, and it always runs with Process ID (PID) 1. It is responsible for starting, stopping, and managing all system services and processes during system startup.

    Q8. Why do we use systemctl?
    systemctl is the command-line tool used to communicate with systemd. It is used to start, stop, restart, enable, disable, and check the status of services. It helps administrators manage services running on the Linux system.

    RHCSA Boot Process (One Paragraph)
    When the computer is powered on, BIOS/UEFI performs POST to check the hardware. It then finds the bootable device and loads GRUB2. GRUB2 displays the boot menu and loads the Linux kernel into memory. The kernel loads initramfs, which contains the drivers needed to find and mount the real root filesystem. After the root filesystem is mounted, the kernel starts systemd (PID 1). Finally, systemd starts all enabled services, and the system displays the login prompt.


Systemd Target (Runlevels)
    In older Linux systems (SysVinit), the operating system used runlevels to define different operating modes.
    | Runlevel | Purpose                |
    | -------- | ---------------------- |
    | 0        | Shutdown               |
    | 1        | Single-user mode       |
    | 3        | Multi-user (Text Mode) |
    | 5        | Multi-user (GUI)       |
    | 6        | Reboot                 |
    A target is a group of services that defines how the system should operate after booting.

    1. multi-user.target : This is text mode.
        Multi-user
        Networking enabled
        SSH works
        No graphical interface (GUI)
    2. graphical.target : This starts everything in multi-user.target, plus the graphical desktop.
    3. rescue.target :  Rescue mode is used when the system has problems but can still mount the root filesystem.
        Single-user mode
        Root filesystem mounted
        Minimal services
        Used for maintenance and repairs
    4. emergency.target : Emergency mode is the most minimal boot mode.
        Very few services started
        Root filesystem may not be mounted automatically
        Networking is usually unavailable
        Used when serious boot problems prevent normal startup

    View the Current Target
        systemctl get-default
    Change the Default Target
        sudo systemctl set-default graphical.target
    Switch Targets Without Rebooting
        sudo systemctl isolate multi-user.target

    Difference Between set-default and isolate
        set-default
            Changes the default target for future boots.
            No immediate change.
        isolate
            Changes the target immediately, without rebooting.

Rescue mode & Emergency Mode
    Rescue mode is a special boot mode used to repair a Linux system.
    systemctl isolate rescue.target
        Only essential services are started.
        The root filesystem (/) is mounted.
        You get a root shell.
        Networking may or may not be available, depending on the situation.
        It is mainly used for system maintenance and repairs.

    Emergency mode is even more minimal than rescue mode.
        Root filesystem may not be mounted.
        Networking is usually unavailable.
        Very few services are running.
        Used when Linux cannot boot normally.
